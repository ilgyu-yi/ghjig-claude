- A `python3` that exits 0 while printing a banner on stdout no longer disables the git command matchers: `strip_command_data` and `space_glued_separators` selected their interpreter by exit status despite declaring a fail-closed contract, so the banner was returned *as* the stripped command — the arm entry-greps missed and the protected-branch, `--no-verify`, force-push, protected-push and `gh pr merge` gates silently allowed; both sites now frame the payload in a constant tag and admit it only on output validity (absent / non-zero exit / exit-0-with-junk / exit-0-partial / stderr-only all return the command unchanged, so an arm can only ever match more), with the rule stated once in SPEC §6.1.2 beside the `_codepoint_len` decimal instantiation.
