- SPEC §1.10 states the author-side evidence discipline for a durable-artifact body: a quotation resolves in the **file** it is attributed to — a string that exists elsewhere in the tree but not at the attributed site is a site-mismatch, the defect an existence-anywhere check passes — while a `:NN` beside the path is informational, since line numbers drift; and a corpus-quantified claim carries the literal command and its literal output, never a prose summary of either, neither broader nor narrower than that output. `/file-issue` and `/file-directive` — the two authoring commands — surface the born-advisory `scripts/lint_citations.sh` report to the author before their reviewer gate; it reads the lexical half of the first part only, exits 0 always, never gates, and a clean report is not verification. The reader searches only files git tracks that resolve physically inside the repository — anything else is reported as out of its reach rather than as a defect — and it states every bound it reaches, since a rung it skipped is not a rung that ruled anything out.
